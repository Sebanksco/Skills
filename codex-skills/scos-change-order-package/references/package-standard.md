# Ownership package and evidence standard

## Evidence rules

- Cite every scope statement to a file and PDF page.
- Record construction sheet number separately from PDF page number.
- Preserve the architect's terminology while explaining the trade impact in plain language.
- Distinguish a verified drawing change from a change described only in narrative or correspondence.
- Do not treat highlighted areas as changes unless the revision/cloud context supports that conclusion.
- Do not double count one change appearing in narrative, drawings, and the subcontractor proposal.
- Mark illegible, missing, superseded, or conflicting documents explicitly.

## Drawing trace columns

Produce one row per affected sheet/detail:

| Field | Meaning |
| --- | --- |
| Sheet | Construction sheet identifier, such as M201. |
| Sheet title | Title block sheet title. |
| Detail/section | Detail, schedule, room, grid, equipment, or other locator. |
| Revision/cloud | Verified revision number and cloud/delta when shown. |
| Issue date | Date shown on the governing document. |
| PDF page | One-based page number in the evidence file. |
| Change shown | Concise description of the actual graphical or schedule change. |
| Trade impact | Why the change affects the proposed subcontract scope. |
| Evidence status | Confirmed, inferred, missing, or conflicting. |

## Ownership summary pages

Match the approved SCOS package exemplar in structure:

1. Header
   - project name and number;
   - architect directive number;
   - PCO number;
   - subcontractor/trade;
   - date prepared;
   - prepared by and reviewed by.
2. Change Order Narrative
   - condition/scope prior to change;
   - description of change;
   - justification/reason cost should be approved.
3. Drawing / Document References
   - one row per affected sheet/detail;
   - revision/cloud reference;
   - description of clouded change;
   - date issued.
4. Itemized Cost Breakdown
   - item description, quantity, unit, unit cost, and total;
   - labor/material subtotal;
   - subcontractor overhead, fee, tax, and bond as actually proposed;
   - subcontractor total;
   - GC overhead and profit;
   - final owner-facing total.
5. Supporting Documentation Checklist
   - subcontractor quote/invoice;
   - itemized breakdown;
   - marked-up/clouded drawings;
   - specification/shop-drawing verification when applicable;
   - schedule documentation when applicable.
6. Schedule Impact
   - time extension requested: yes/no;
   - number of days;
   - supporting explanation when nonzero.

## Attachment order

Append supporting files in this order unless the user directs otherwise:

1. unmodified subcontractor proposal/letter;
2. subcontractor pricing summaries and detailed backup;
3. architect PCR/ASI/RFI/CCD or other directive;
4. referenced marked-up construction-document pages;
5. relevant correspondence or specification support.

## Review gates

| Gate | Required result |
| --- | --- |
| Evidence completeness | Every cited source is present and readable. |
| Drawing trace | Every claimed drawing change has page-level evidence or is marked missing/inferred. |
| Scope alignment | Proposal scope maps to the applicable architect changes without unrelated work. |
| Cost reconciliation | Line items, markups, proposal total, GC O&P, and final amount reconcile within $0.01. |
| Package QA | Page order, readability, totals, checklist, and schedule impact are verified. |
| Ownership approval | Explicit human approval, date, and approved values are recorded. |
| Posting | Authorized SCOS write is re-read and verified. |

Any unresolved scope or monetary conflict blocks the next financial gate.
